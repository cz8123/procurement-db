## 8) 表头「饱满度」色条（Column Quality）
- 用户要求：「表头像 power query 那样，用颜色显示这列数据的饱满度」。
- **实现**：`th` 内部加一条 5px 色条 `.tf-qb`，绿段=有效值占比、灰段=空值，宽度即百分比。悬停出浮层（有效/空/去重值/总行数），点色条直接打开值面板看分布（`stopPropagation` 防止连带弹列菜单）。
- **后端** `transform.column_stats(con, source, steps, upto)`：**一条 SQL** 算完全部列（`COUNT(*)` + 每列 `COUNT(col)`、`COUNT(DISTINCT ...)`、`SUM(CASE WHEN ...='')`），不逐列查询。35 列 × 4.5 万行实测 **1.06s**。
- **口径两处关键决定**：
  - 「空值」= `NULL` **或** 空白字符串（Excel 导出空单元格常是 `''`，看着就是空的，算成有效值会让饱满度假高）。用 `SUM(CASE WHEN col IS NULL OR TRIM(CAST(col AS TEXT))='' THEN 1 ELSE 0 END)`。
  - 「去重值」用 `COUNT(DISTINCT NULLIF(TRIM(CAST(col AS TEXT)),''))`，空白串归一成 NULL 不计入，否则会出现「空值 2 个、去重值 5 个」里含一个空白值的自相矛盾。
- **异步不阻塞**：预览 300ms 先出，统计请求 120ms 防抖后发，色条先是 `pending` 渐变 shimmer，回来自动上色（`tfPaintStats` 只改色条 DOM，不重绘整表，保住滚动位置）。渲染令牌 `_tfStatsTok` 丢弃过期响应；`tf.statsKey = source|upto|JSON(steps[:upto])` 命中直接复用，不重复请求。
- **踩的坑**：
  - **统计没回来时不要先涂成「无数据」灰条**：`tfPaintStats` 原逻辑在 `tf.stats=null` 时给色条加 `nodata`（死灰），用户看到一片灰会以为表里没数据。改为 `if(!cols) return;` 保持 pending 动效。
  - **`nodata` 类加上后忘了移除**，拿到数据后绿色被 `.tf-qb.nodata i.ok{background:#c4cdd9}` 盖成灰的（看着像没生效）。补 `qb.classList.remove("nodata")`。
  - **`COUNT(DISTINCT)` 忽略 NULL 但会算空白串**，与「空值」口径打架，故 not null 与 distinct 都要 `NULLIF(TRIM(...))` 归一。
  - 测试里等"质量条上色"不能判断 `!pending`（首帧 nodata 也满足），要等 `qb.querySelector("i.ok")` 出现；同理全空列要等 `i.nu`。
- **视觉/交互细节**：单值列（`distinct<=1` 且有效>0）绿条调暗 `.ok.dim`，提示"满但没信息量"；「支出子类」43.8%/56.2%、「CAPEX 项目批准参考号」0.14% 一眼可见；浮层 `pointer-events:none`（鼠标移开即消失，不挡表格）、不越出视口、标题 `max-width:276px` 省略。

### 8b) 性能优化：砍掉 COUNT(DISTINCT)
- 实测各部分开销（35 列 × 4.5 万行）：完整版（distinct+trim）1.02s / 只算饱满度 0.16s / distinct 不 trim 0.66s —— **COUNT(DISTINCT) 占 85%**。
- 决定不算 distinct：「整列是否只有一个取值」改用 `MIN(NULLIF(TRIM(col),''))` 与 `MAX(...)` 比较（几乎零成本），浮层文案相应从「去重取值 N 个」改为「共 N 行 · 整列只有 1 个取值」+ 点击看分布。整表统计降到 **0.37~0.60s**。
- 单值判定要注意：全空列 min/max 都是 NULL，必须加 `filled > 0` 前置条件，否则全空列会被判成"单值"而把绿条调暗（本来就没绿条，但语义错）。
- 最终测试：`test_colstats` 30 项、`tf_qb_check` 29 项，合计 **283 项全绿**。

## 9) 日期类型转换全变 null —— 根因与修复
- 用户报：「关于日期类型，转换数据后都变成了 null」。
- **根因**：`_apply_change_type` 的 date 分支只写了 `date(列)`，而 SQLite 的 `date()` **只认 ISO 8601**（`YYYY-MM-DD`）。真实数据里三种格式全军覆没：
  | 列 | 实际值 | date() 失败率 |
  |---|---|---|
  | `fct_prpo.框架合同到期日` | `2025/4/30`、`31/5/2025`、`30-Sep-22` | 290/325 |
  | `fct_prpo.供应商 AVL 到期日期` | `12/24/2025`、`2025/12/18` | **400/400 全挂** |
  | `fct_prpo.说明` | `2024年7月1日至2025年6月30日…`（自由文本） | 17/17 |
- **修复：纯 SQL 多格式解析**（`_date_parse`），不注册 Python 自定义函数 —— 视图要能被 Power BI 通过 ODBC 直接查，自定义函数会 `no such function`。5 层辅助 CTE：
  1. 去时间(`instr(' ')`) + 分隔符归一（`/ . 年 月`→`-`，`日`→``），首段非数字直接短路 NULL
  2. `substr`+`instr` 拆三段 `_p1/_p2/_p3`
  3. 月份段转数字（英文缩写 12 层 REPLACE，**只在含字母时展开**，CASE 惰性求值）
  4. 判年/月/日：`_p1` 四位→年在前(y-m-d)，`_p3` 四位或两位→年在后；后段里某段 >12 就认定它是日，都 ≤12 走 `date_order`（auto/dmy/mdy/ymd，默认 mdy）
  5. `printf('%04d-%02d-%02d')` 拼回 ISO + 校验
- **实测全部命中**：提交日期 44,987/44,987、框架合同到期日 13,659 ISO + 97 原值、AVL 44,894 ISO + 28 原值。
- **三个口径决定**：
  - 解析不出时**默认保留原值**（`keep_raw=True`），不静默丢数据；步骤里可关掉改成置 NULL。`说明` 这种自由文本列改成日期后原样留着，用户一眼看出「没转成」。
  - 校验用 `date(iso) = iso` 而不是 `IS NOT NULL`：SQLite 会把 `2024-02-30` 静默修正成 `2024-03-01`，只判非空等于放行不存在的日期。年份还要求 1900–2100。
  - 年在前格式（`2024-13-01`）**不做月日换位**：那显然是「13 月」写错了，应判失败保留原值，不能猜成 1 月 13 日。
- **踩的三个坑**：
  - **`date()` 对 `'45000'`（Excel 序列号）会返回 `-4589-02-08`** 而不是 NULL，所以不能只靠 `date()` 判真假。
  - **ISO 快通道不能只看 GLOB 格式**：`'2024-13-01'`/`'2024-02-30'` 格式都对但日期非法，快通道直接放行就变 null 了。加 `date(substr(...,1,10)) = substr(...,1,10)` + 年份范围才安全。
  - **CTE 会被 SQLite 内联展开**：`_m1/_m2` 在年/月/日表达式里被引用七八次，12 层 REPLACE 于是重复求值数十次。加 `AS MATERIALIZED` 反而更慢（要连 35 列一起物化），最后靠「删掉 `_m3`（年在前时日必定是数字，不需要月份映射）+ 减少重复引用」把脏列从 7s 降到 2-3s。
- **性能三个数字**（4.5 万行 × 35 列）：预览 94ms、ISO 列全表 0.11s、脏列全表 2.4-3.0s、质量统计 0.8s（无转换）/3.6s（脏日期列）。
- **预览秒开的关键不是表达式优化，是别让它跑**：`preview` 的 `COUNT(*) FROM (sql)` 会强制全表求值日期表达式（14s）。新增 `_ROW_PRESERVING` 集合（keep/remove/rename/change_type/replace/clean/split/extract/add_column/sort/fill_down 都不改行数），命中就直接 `COUNT(*) FROM 源表` → 14s 降到 70ms。`column_stats` 同理用 `WITH _m AS MATERIALIZED` 避免同列在 SUM/MIN/MAX 里被算三次。
- **顺带修的 bug**：`change_type` 转数字后没清 `store='text'` 标记，表头一直标着「声明数字实存文本」的黄色 ABC 告警（转了数字也不消）。改成转换后 `store=None`。
- **前端**：`tfTypeOf` 认 `c.date` 标记 → 表头显示绿色 `YMD`（SQLite 只能把 ISO 日期存文本，没这个标记会一直显示 ABC）；`TF_FIELDS.change_type` 加「日期顺序」下拉 + 「认不出时保留原值」勾选，`/api/transform/meta` 加 `dateOrders`。
- **测试**：新增 `tests/test_date_convert.py` **51 项**（16 种真实日期形态、空值/自由文本/非法日期/越界年、keep_raw 开关、order 强制、列元数据、日期列排序、与分组筛选组合、真实库三列回归）、`tests/tf_date_check.js` **17 项**（点表头改日期→表头变 YMD、值真变 ISO、配置面板出现日期选项、切 dmy 重算、质量条跟随、自由文本不清空、清空步骤恢复 ABC）。回归合计 **351 项全绿**（60+39+30+54+51+31+40+29+17）。
- 真实库仍干净：`transform_query` 0 条、无视图、20 张表。

## 11. 改类型报错提示梳理 + 修「假成功 toast」

**用户问「修改字段类型有哪些报错提示」**，梳理后分三层。

**会报错的（预览区红条 `.tf-err`，非 toast；文案统一带「第 N 步（更改类型）：」前缀）**：
1. `列「X」在当前结果中不存在` —— 前面步骤删了/重命名了该列（最常见）
2. `不支持的日期顺序：ydm` —— `date_order` 非法（仅 API/手改 步骤 JSON 会触发，UI 下拉只有 auto/dmy/mdy/ymd）
3. `不支持的目标类型：float` —— `type` 非法（UI 只有 4 个）
4. `列「None」在当前结果中不存在` —— 缺 `column` 参数
5. `SQL 执行失败：<sqlite 原文>` —— 兜底（`app.py` api_tf_preview 的 sqlite3.Error 分支）
前 4 条都在 `transform.compile_query` 里 `raise TransformError`，被包成 `第 {i+1} 步（{STEP_LABELS[op]}）：{e}`。

**不会报错的静默行为（这才是用户困惑点）**：
- **转数字：非数字文本一律变 `0.0`**。`num_expr()` 只是 `REPLACE` 去 `¥`/`,`/空格 后 `CAST(... AS REAL)`，SQLite 把 `'abc'`/`'N/A'`/`'-'` 全 cast 成 0，无任何提示。实测「公司」列转 number 全变 0.0。
- 转整数：`3.7 → 3`，直接截断不四舍五入。
- 转日期认不出：`keep_raw` 默认勾选 → **保留原值**；取消勾选 → NULL。实测「框架合同到期日」44,987 行：ISO 13,667 / NULL 31,223（原本就空）/ 认不出保留原值 **97 行（全是 Excel 序列号 46055、46327、45747…，即 2026-02-02、2026-11-01、2025-03-31）**。`_date_parse` 目前不认 5 位序列号 → 这 97 行转换后仍是数字，看着像「没生效」。**待办：加 Excel 序列号分支（20000–60000 区间按 1899-12-30 起算）**。

**表头视觉提示（不是报错）**：类型标记 `ABC/123/1.2/YMD`；黄色 ABC = 「声明 REAL 实存文本」（`store='text'`）告警；绿色 YMD = 已是日期；质量条单值列绿条调暗。

**修掉的 bug**：`tfTypeMenu`/`tfColMenu` 的 chip 原来在 `tfQuick()` 之后**立即** `toast("已将 X 改为日期")`，而 `tfQuick` 里的 `tfPreview()` 是异步的 —— 后端报错时先弹绿字「已改成功」、再在预览区出红框，明显自相矛盾。改法：`tfPreview` 返回 `!tf.err`，`tfQuick` 返回该 Promise，两处 toast 改成 `.then(ok=>{ if(ok) toast(...) })`。

**测试**：`test_transform_api.py` 加第 9 段 **8 项**（4 条错误文案 + 4 个 400），该文件 47→**55**；新增 `tests/tf_type_err_check.js` **14 项**（红框出现、文案含步骤前缀、`#tfPrevInfo=有错误`、失败时不弹假成功、非法日期顺序文案、成功后表头变 YMD、还原文本、无真实 JS 报错）。注意：故意制造的 400 会让浏览器 console 记 `Failed to load resource`，断言里要过滤掉。

## 12. 列表视图金额汇总恒为 0 —— 裸 CAST 未洗币符（真 bug，已修）

**用户报**：「为何含增值税总价改为小数了，列表视图中汇总还是 0」。

**根因**：`app.py` 的 `api_rows` 汇总用 `SUM(CAST(qc AS REAL))`，**没有洗 `¥`/`￥`/`$`/`HK$`/千分位/空格**。`'含增值税总价'` 在 `fct_prpo` 里声明 REAL、实际 44,986 行全是 `'¥30,000.00'` 文本 → 裸 CAST 全部得 0 → 合计恒等于 `0.0`。这是记忆里早就记录过的坑（「金额列声明 REAL 实存文本，裸 SUM()=0.0」），但只在 `transform.py` 用 `num_expr()` 挡住了，`app.py` 这三处漏了。

**同一根因的连带问题（一并修）**：
- 金额筛选：`_build_where` 用 `CAST(...) > ?` → `'¥1,200,000.00'` 也是 0 → 筛「>100 万」一条都匹配不到。
- 金额排序：`ORDER BY qid(sort)` 按字典序 → `'¥9,362.05'` 排在 `'¥30,000.00'` 前面。

**改法**（`app.py`）：
- 新增 `_NUM_TYPES = {REAL,INTEGER,NUMERIC,DOUBLE,FLOAT,DECIMAL}` + `_is_num_type(t)`（按 `(t or "").upper().split("(")[0].strip()` 判断，含注释说明 SQLite 只看声明）。
- 汇总 4 个聚合全部改 `tf.num_expr(db.qid(c))`，`COUNT` 仍用原列（真非空计数）。
- `_build_where` 的 `is_num` 改用 `_is_num_type`，数值比较全部走 `tf.num_expr(qc)`。
- 排序 `sort_expr = tf.num_expr(...) if _is_num_type(...) else qid(sort)`。
- **顺带**：数值列判断从 `== "REAL"` 放宽到整个数值类型集合 → INTEGER 列（数量类）现在也能汇总、也能用数值筛选符。
- 前端 `templates/index.html`：新增 `NUM_TYPE_SET` + `isNumCol(c)`（与后端同口径），替换 `state.coltype[c]==="REAL"` 三处（合计行右对齐、筛选面板操作符列表）。

## 13. 数据质量页重构：新增「字段取值清洗 · 整合相似文本」

**用户指出的定位**：「维度表与数据映射质量完整性检查的作用，是在统计分析时可以自定义清洗、整合相似文本，用映射后的字段展示可视化」。原来的功能只围绕「孤儿率 → 补录」（补齐缺失成员），方向反了 —— 补录会**生产**更多变体，而分析时需要的是**合并**变体。

## §14 重做「数据质量」→「映射聚合」（用户第 6 次需求）

**要求原文**：重做数据质量这个模块，叫做映射聚合：①可手动选择哪些表的哪些字段做聚合；②字段可先去重导出、再上传文件导入映射规则；也可自动整合同类项、自动创建映射字段、二次手动修改；最后生成聚合维度表；③创建后自动在模型视图创建关联。

**核心判断：聚合维度表是「桥接表」，不是改源表。** 表结构 `id | 原始值(PK) | 聚合值列 | 源行数 | 写法数`。事实表仍按「原始值」关联（因为映射是照抄源字段去重出来的，孤儿率天然 0），可视化改用「聚合值」分组。这样「合并规则」变成一条可编辑、可导出、可复用的数据，源数据一个字节都不动 —— 与上一轮 `clean.apply_merge`（UPDATE 源表）方向相反，旧「取值清洗」整节下线。

**新增 `aggmap.py`（374→560 行）**
- `auto_map(con, table, col, mode, threshold)`：先按 `clean.norm_key` 精确分组（规范值仍按 `ugliness` 挑）；`mode=fuzzy` 再叠加相似度聚类（并查集 + 预计算 Counter 的 quick_ratio 上界 + 长度差剪枝，**规范化后 >800 个取值直接拒绝**，提示改用导出/导入；>50000 截断）。
- `parse_mapping(bytes, filename)`：CSV(UTF8-BOM/UTF8/GBK)/XLSX，认「原始值/聚合值」表头别名，无表头按前两列；聚合值留空回退原值。
- `build()`：校验表名（`^dim_[中英文数字_]{1,40}$`，重名拒绝）→ 建表 → 写 `agg_task` → 建 `map_config` 关系（主关系 + `relations` 附带）→ `disable_existing` 时**停用同一源列上所有其它关系**（否则 Power BI 里一列两条关系，一条只能非活动）。
- `refresh_task()` 补入源表新增取值（1:1）+ 重算写法数；`drop_task()` 删关系→删表→删任务。

**动态表登记（关键坑）**：`dim_agg_*` 是运行时建的，不在 `db.KNOWN_TABLES` 里 → 侧栏/模型视图/关系下拉全看不到。做法：`app.AGG_TABLES` + `register_agg_table()` 同时写 `KNOWN_TABLES` 与 `TABLE_LABELS`；`load_agg_meta()` 在启动时按 `agg_task` 恢复（**必须放在 `get_con` 之后**）。`_table_meta()` 来源显示「(聚合维度表)」。

**前端同页两标签**（`#agg`）
- 标签一「映射聚合」：①表+字段下拉→扫描（摘要：249 取值 / 44691 行 / 聚合后 145 / 合并 104）→ ②映射表（每行一个原始写法，聚合值是可编辑输入框，虚线底提示可改；勾选+批量设为；筛选/只看已合并；分页 150）+ 自动整合（精确/智能+阈值）+ 导出 CSV/xlsx + 导入 → ③生成（任务名/表名/聚合值列名、☑建关联、☑停用旧关系、查找其它引用列）→ 任务卡片（编辑映射/刷新取值/模型视图/删除）。
- 标签二「质量检查」= 原关系健康度 + 自定义规则，关系行新增「聚合此维度」按钮（`aggPreset`）。
- 扫描**维度表**的字段时，后端顺手 `scan_cascade` 返回 `refs`，前端预选这些事实列一起建关系 —— 否则新表只能通过「事实→原维度→聚合维度」两跳访问。

**踩坑**
