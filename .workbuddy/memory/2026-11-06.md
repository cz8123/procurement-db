## 追加：dim_company_map 主键改为 1 起自增（用户要求）

### 为什么必须重建表
SQLite 只有 `INTEGER PRIMARY KEY` 才是 rowid 别名、才自增；原表是 `TEXT PRIMARY KEY`（值来自 CSV 的 491–552），
`ALTER TABLE` 改不了列类型 → 只能 CREATE 新表 + INSERT SELECT + DROP + RENAME。

### 做法
新增 `reid_table.py`（通用工具，不只修这一张）：
- 参数：`表名 [主键列=id] [--dry-run]`；已有视图/触发器依赖会先拒绝（DROP+RENAME 会被阻塞）。
- 整段 DDL 在单事务内；重建后**逐行逐列比对**（新 id 必须 1..N、其余列内容必须一致），任一不符 raise → rollback。
- 改前写表级快照 `backups/<表>_before_reid_<时间>.json`（含旧 DDL + 全表数据），不复制 111MB 全库。

执行结果：62 行，id **1–62**，`typeof(id)=integer`，`sqlite_sequence=62`；顺序按原 id 升序（1=江门悦之宝=原 491）；差异单元格 0。
备份快照 `backups/dim_company_map_before_reid_20261106_174518.json`。

### 连带发现并修掉的 bug
id 变 INTEGER 后被 `_is_num_type()` 当数值列 → 表底出现「Σ 1,953」（1..62 求和），毫无意义。
修法：`api_rows` 里 `pk_col = get_pk(table, con)`，`num_cols = [c for c in cols if _is_num_type(...) and c != pk_col]`。
**排除主键而非排除 id**——业务主键（单号）同样不该求和。事实表主键是 `表单编号`(TEXT)，不受影响。

### 验证
- 自增：事务内连插两条得到 63、64，回滚后行数仍 62、seq 仍 62；真实前端「新增一行」端到端插出 id=63（随后删除并 `UPDATE sqlite_sequence SET seq=MAX(id)` 复位，无空洞）。
- 字符串主键兼容：`WHERE id='5'` 命中（前端 PUT/DELETE 传的是字符串），返回「海南宝悦」。
- 关系不受影响：孤儿仍 131/44987（0.29%），`fct_prpo.公司 → dim_company_map.Company` 未动。
- 前端：表格 id 显示 1..62、表底无 Σ；`/api/tables/dim_company_map/rows` 的 `aggregates == {}`。
- 回归：`test_pages_crud` 57 项（原 54 + 新增 3）、`grid_sum_check` 13、`tf_ui_check` 32 全绿。
- 顺带核对：`1,654,497,825.74` 是 **fct_po** 的「总采购订单总额」，不是 fct_prpo 的；fct_prpo 含税总价 1,595,319,937.32 本来就不同，无回归。
- 截图：`界面-公司维度表-自增ID.png`。

## 新增行不再要求手填 ID（同日 18:10）

用户反馈：id 改成自增后，界面「新增一行」还是摆着 id 输入框，以为必须填。

### 改动
- `app.auto_pk_cols(table, con)`：单列主键且声明类型恰为 `INTEGER` → rowid 别名，可自动分配（`TEXT` 主键如「表单编号」不计入；复合主键不计入）。
- `/api/tables/<t>/schema` 每列多返回 `auto` 布尔。
- `POST /api/tables/<t>/rows` 回传 `{"ok":true,"id":<lastrowid>}`（仅自增表）。
- 前端 `openEditor(null)`：自增主键输入框 **disabled + 占位「保存后自动生成」**，标签角标「自增」，表单顶部一条说明条；保存后用 toast 报「已新增一行 · ID 63」。
- `.field input:disabled` 文字色 `--muted` → `--text-2`：原色在浅底仅 **2.81:1**，几乎看不见（编辑行锁定的主键也受影响），现 6.28:1 / 暗色 8.54:1。

### 验证
- 新增 `tests/auto_id_check.js`（15 项）：置灰、占位、角标、说明条、普通字段仍可编辑、保存后 toast 带 ID 63、落库 id=63、无 JS 报错。亮/暗各截一张。
- `test_pages_crud` 57 → **65**（新增 8 项：schema auto 标记、非主键不标记、TEXT 主键表不标记、不传 id 成功、id=seq+1、落库一致、id 传空串仍自增、测试行清理）。
- **断言要用 `sqlite_sequence` 而不是 `MAX(id)`**：删掉最后一行后 MAX 会回退、seq 不回退，第一版断言就因此误报（64 vs 63）。
- 真实库测完已复位：62 行、seq=62，无空洞。

### 边界
- `fct_company_location` 的 id 也是 `INTEGER` 主键，同样置灰（代理键，自增合理）。
- 想在新增时指定 id 目前做不到（只能改库或走导入）。用户没这个需求，先不做开关。
