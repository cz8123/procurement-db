## 映射聚合导入升级：第一列原始值 + 其余列按表头建附加字段

用户要求：「按表头建附加字段，第一列是原始值，但是可以自定义表头，后面都是映射列字段」。此前只认前两列（原始值/聚合值），三列文件第三列被丢弃。

**解析（aggmap.parse_mapping，新增 is_known 参数）**
- 表头判定两条路：① 认得出「原始值/聚合值」别名；② 传了 `is_known` 时，首行一个已知取值都没有、第二行有 → 首行是表头（覆盖「部门cn/部门en」这种自定义表头）。
- 列角色：**第一列永远是原始值**（不看名字）；只有表头明确写「聚合值」的列才是聚合值，**没有这列时 `agg=None`**（表示"不动聚合值"，由调用方沿用库里/屏幕现值），不再打回 1:1。
- 其余列＝附加字段，名字取表头（`_col_name_fix` 去空白/标点、非法字符转 `_`、重名加序号、非字母开头加 `c_`），改名有 `renamed` 记录供提示。
- 旧导出文件里的「行数/写法数」列自动跳过；整列为空的列不建。
- 返回 `records[{raw,agg,extra}] / extra_cols / renamed / agg_from_file`，`pairs` 保留兼容。

**写库**
- `_normalize_rows` 保留行内 `extra`（空串=没提供，不覆盖手工值）。
- `build()`：声明列 + 行内出现的键一起建列，插入时一并写值（不再只建空列）。
- `rewrite_mapping(extra_cols=)`：先 `ALTER TABLE ADD COLUMN` 补新表头，再按原始值 diff；只更新文件提供了值的附加字段，留空不动，新行按 `ex.get(col)` 插入。
- 打开页时的保存链路（PUT）透传 `extra_cols`；`/api/agg/scan` 返回 `extra_cols`（来自 `extra_columns`）。

**导入对齐（/api/agg/import）**
- 新增 `base` 参数：前端把屏幕上这份映射（raw/agg/extra）一起发过去当基线。**文件里没有的取值、文件里留空的附加字段都保持现状**；无 `base` 时基线取库里已保存映射，再退到自动整合建议。修掉了「导一个局部文件就把其余合并打回 1:1」的隐患。
- 响应带 `extra_cols`、`stats.agg_from_file / renamed`。

**导出（/api/agg/export）**：表头变成 `原始值,聚合值,<附加字段…>`；不传 rows 时按维度表现状导出，POST 时用行内 extra。回导不丢。

## 框架协议分析视图 vw_fa_analysis（12:47）
用户澄清分析视角：**以框架协议为主**（不是 PRPO），带出前置审批预估金额 + PRPO 实际采购额；不再迁就 Power BI，后续方向是**手写 HTML 前端可视化**，Power BI 转辅助。

**建视图**（备份 `procurement_before_fa_view_20261118_1247*.db`）：
`fct_framework_agreement`（190 恒定）← LEFT JOIN `fct_preapproval`（预估金额）← LEFT JOIN PRPO 聚合（实际采购额/单据数/门店数/供应商数/首末日期）；派生 `执行率`、`在有效期内`、`剩余天数`、`预估金额_可加`。31 列。

**关键发现（必须记住）**：
1. **预估金额不能直接 SUM** —— 7 个前置审批单被 18 份框架协议共用（FAPA-0000065/69/76/77/82/107/110），行级 64,131 万 vs 去重 58,299 万，**虚高 5,832 万**。视图加 `预估金额_可加`（窗口函数 `ROW_NUMBER() OVER (PARTITION BY 前置审批单号 ORDER BY 参考编号)=1` 才给值），汇总必须用它。
2. 金额两表都是 TEXT（`'¥4,106,550'`），用 `transform.num_expr()` 清洗；空串要 CASE 转 NULL，否则 CAST→0 被计入 SUM。
3. 口径：190 条 / 176 有前置审批 / 164 已采购；预估 5.83 亿、实际 2.25 亿、**整体执行率 38.6%**；CP 34.1% / AAP 43.1% / DT 65.4%。
4. **105 条执行率 <50%** —— 框架协议是额度上限不是目标，不能当"执行不力"讲；10 条 >150%（`SDHS-PART/2025/018/20250520` 预估 6.5 万 / 实际 69.9 万 = 10.8 倍，疑预估填错）；**71 条已过期仍在被 PRPO 引用**。

**注册方式的坑**：一开始把视图塞进 `KNOWN_TABLES`，结果 `/api/tables` 走元数据分支给出 `kind=fact / readonly=false`（可编辑），且 `test_pages_crud` 主键断言失败。**正确做法**：`/api/tables` 本来就会自动追加库内所有视图（`kind=view/readonly=true`），只需在 `TABLE_LABELS` 登记中文名，并把追加分支改成 `label=tf_label.get(v) or table_label(v)`、`desc=table_desc(v) or 默认`、`source=(转换视图)/(分析视图)` 区分。已回退 KNOWN_TABLES/tkind/src 三处改动，测试改为断言时跳过 `vw_` 前缀。回归 pages_crud 65/65、drop_table 33/33 通过。

**给 HTML 前端的数据取法**：`GET /api/tables/vw_fa_analysis/rows?size=200`（190 行一次拿完，size 上限 200），支持 `sort/order/search/filters`。
