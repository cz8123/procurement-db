## §1 增量导入 + 聚合附加字段（四条需求落地）

用户提出四条需求（原话见下），已全部实现并验证：
> 一、补充聚合两个功能要求：1、聚合映射表支持添加多个字段，除了需要聚合映射的字段，可以手动添加一些其他的字段
> 2、如果新数据导入数据库，要能识别提示已聚合映射的字段有新增的文本类型需要补充映射
> 二、数据库的导入功能：1、需要增量导入，能识别之前的数据，以及新增的数据。2、虽然事实表原则上不能修改，
> 但是事实表也是从其他数据库导出的，可能有修正，如果新增导入的数据和之前的有冲突，要有冲突提示以及解决方案
> （覆盖、新增字段等措施选择）3、如果历史字段做过改类型的操作，在新导入数据后，应该直接同步修改，
> 但如果有冲突比如哪些数据改不了（会变null等错误），要有提示和解决方案

### 用户确认的三个取舍（问过两轮，第一轮术语太抽象被说"没明白"，改用 PR-2025-001 金额 30 万→32 万的例子才对齐）
1. 冲突默认：**先告诉我，我确认才覆盖**（不动事实表）
2. 覆盖粒度：**整行盖，但可勾只盖某几列**
3. 聚合附加字段：**全部我手工填**（不做从源表自动带出）

### 一、聚合维度表附加字段
- `aggmap.build(..., extra_cols=[{name,type}])`：建表时追加自定义列，类型支持 text/number/integer/date
- `aggmap.add_columns()`：给已有表 `ALTER TABLE ADD COLUMN`，幂等（已存在跳过）
- `aggmap.set_extra_values()`：批量写值 `[{raw, extra:{列:值}}]`，未知列名回报不报错
- `aggmap.extra_columns()`：识别「非保留列」的附加字段
- `aggmap.task_rows()` 带出 `extra:{列:值}`，前端能显示/编辑
- **`aggmap.rewrite_mapping()` 重写**：原来是 `DELETE FROM dim` + 重插，会把手工填的附加值全冲掉。
  改成按原始值 diff —— 消失的删除、新增的插入（附加列 NULL）、仍在的只 UPDATE 聚合值/行数/写法数。
  实测：填 `DepartmentEn=Admin` → 改 3 行聚合值 → 附加值仍在。
- 保留列（id/原始值/源行数/写法数/聚合值列）不能占用，非法列名（含空格）被拒
- 前端：建表表单加「附加字段」区（可加多行，列名+类型+删除）；编辑态显示已建字段 chip +
  「新列名+类型+添加字段」+ 折叠的「给附加字段填值」表格（原始值 × 各列 input，一次保存整表）

### 二、导入后提醒聚合字段有新取值
- `aggmap.pending_values(con)`：遍历 `agg_task`，算「源表取值 − 维度表原始值」差集，
  返回 `{task_id, dim_table, name, source_table, source_col, new_count, new_rows, samples, values}`。
  只做差集不跑孤儿率，避免导入后被拖慢。
- `/api/import` 返回 `pending_agg`；前端结果下方黄色提示条 + 「补入（1:1）」按钮（复用 refresh 接口）
- `/api/agg/pending` 独立接口，聚合页/其它地方也能查

### 三、增量导入 + 冲突处理
- `app.classify_import(con, table, rep)`：
  - 把上传主键写进 `temp._imp_pk`，再 `JOIN` 回查库里已存在的行（避免 48k 个 `IN` 参数超限）
  - 分 `new` / `same` / `conflict`，冲突给字段级差异 `[{col, old, new}]`（最多 50 条样例）+ 按字段聚合的 `conflict_fields`
  - **比较范围 = 文件实际提供的列**（`updatable_cols`），文件里没有的列不参与比较也不会被覆盖
  - 金额列用 `db.parse_amount()` 数值比较（`'¥30,000.00'` 与 `30000` 视为相同），其余 trim 文本比较
  - 另返回 `conflict_keys`（全量，只在执行时用，预览接口 pop 掉）和 `file_cols_not_in_db`
- `app._apply_conflicts()`：`skip` 不写 / `overwrite` 整行 / `fields` 只盖勾选列；只对冲突行 UPDATE
- `app._backfill_cols()`：勾「加到事实表」加列后，把新列的值回填到**已存在行**
  （`INSERT OR IGNORE` 对已存在主键是跳过的，不回填等于白加 —— 这是测试抓出来的真 bug）
- `/api/import-preview` 返回里加 `plan`；`/api/import` 增加 `conflict_mode` / `conflict_fields` / `add_missing_cols`
- 前端：校验后多一排判定卡片（纯新增/与库一致/有冲突）+ 黄色处理区（3 单选 + 字段勾选 + 明细表默认展开）
  + 「库里没有的列」勾选区；选覆盖会二次确认

### 四、类型转换同步与失败提示
- `app.type_risks(con, table, rep)`：查 `transform_query` 里该表的 `change_type` 步骤（含日期），
  用同一规则预跑上传数据，报「多少行转不出来 + 样例值」
- **关键认知**：视图是查询期求值，新数据导入后自动跟随，**不需要重跑转换**；
  只有物化表（output_mode=table）才需要点「刷新」
- **另一个关键认知**：SQLite `CAST('abc' AS REAL)` = **0.0 而非 NULL**，金额类转换失败是静默变 0，比变 NULL 更危险。
  但金额列在 `_analyze_rows` 阶段就被 `parse_amount` 解析成 None 了（已有 `amount_warn` 提示），
  所以 `type_risks` 主要覆盖「用户手动转类型的非金额列」

## §4 三项收尾优化（绑定地址 / 口令 / 导出流式 / 连接调优）

### 需求
用户「全改3项」——即上一轮体检遗留的：服务绑 `0.0.0.0` 零鉴权、导出全内存、`cache_size` 仅 2MB。

### 改动
- **绑定默认回到 `127.0.0.1`**（原 `0.0.0.0`）。要共享再显式 `HOST=0.0.0.0`；此时若未设 `DBADMIN_TOKEN` 启动会打醒目警告。
- **口令门（可选）**：`DBADMIN_TOKEN` 设置后 `before_request` 全站拦截，支持 `?token=xxx`（首访写 HttpOnly cookie，7 天）、`X-Token` 头。`hmac.compare_digest` 比对。
- **`/api/shutdown` 只认本机回环**：`remote_addr` 非 127.0.0.1/::1 一律 403。即便服务被暴露到局域网，远程也不能关。
- **导出改流式**：`Response(stream_with_context(gen()))` + `fetchmany(8000)`。生成器内部**另开只读连接**（请求期的 con 在响应返回时就关了，生成器之后才迭代）。**不设 `row_factory`，用 `writerows` 按下标写**——按列名逐行取值实测慢 3 倍（190 万次哈希查找）。
- **`_CON_PRAGMAS`**：`cache_size=-65536`(64MB) / `busy_timeout=8000` / `temp_store=MEMORY`，`get_con` 与 `_ro_con` 共用。
- `start-dbadmin.bat` 注释同步（默认仅本机 + 局域网口令用法）。

### 验证
- 默认启动实测只监听 `127.0.0.1:5000`，用本机网卡 IP 访问连不上（HTTP 000）。
- 口令：无 token 401 / 错 token 401 / 正确 200 且下发 `Set-Cookie` / 仅 cookie 200 / `X-Token` 头 200。
- 导出：fct_prpo 44987 行、53,817,016 字节与库逐条一致（尾批 4987 行不丢）；fct_po 48007 行一致。热态 3.5s。
- `PRAGMA` 实测 cache_size=-65536、busy_timeout=8000、temp_store=2。
- **新增 `tests/test_export_stream.py` 21 项**：跨批完整性、BOM、下载头、cols/search/filters/sort、视图可导出、空结果、未知表 404。
- 修 `tests/test_transform_api.py` 过期断言：「源表>=16」→「已登记表都能作源」（库现在 9 个对象，写死表数必挂）。
- 合计 **664 项全绿**（后端 464 + 前端 200）。

### 坑
- PRAGMA 不跨连接持久化，每次 connect 都要重设；`_ro_con` 也要设（只读连接一样吃缓存）。
- 生成器内不能复用视图函数的连接（此时已 close）。
- `_EXPORT_CHUNK=2000` 比 8000 慢约 40%（socket 写次数 × 4），最终定 8000（~4-9MB/批）。
