# 采购分析看板 · 前端复刻实现路径（v1 规划）

> 目标：把 `参考powerBI项目` 里的 PBIP（16 页 / 122 度量值 / Sime 主题）复刻成可独立运行的 Web 看板，视觉对象、DAX 口径、配色与 PBIP 一致。
> 本文件是**路径规划**，不是代码。文末列出必须由你拍板的 4 个决策。

---

## 0. 结论速览

1. **PBIP 是唯一基准**：7 个可见页 + 4 个隐藏页 + 3 个工具提示页 + 1 个测试页，画布固定 1280×720，主题为 Sime 8 色（`#0E385E` 深海军蓝 / `#FF6B12` 橙）。
2. **数据必须与 PBIP 同源**：PBIP 的事实表是 `采购分析报表.xlsx`（41,847 行 × 34 列，已加工宽表），不是 `procurement.db` 的 `fct_prpo`。要做到"数值对得上"，前端必须先用这份 xlsx。
3. **DAX 全部可迁移**：122 个度量值中 105 个是聚合/占比/时间对比/格式化，用 SQL + 前端格式化即可等价；17 个涉及中位数、动态窗口、累计占比、颜色度量，需要专门处理（见 §5）。
4. **自定义视觉需要等价替代**：Chord、ClusterMap、geos_bi、Deneb、分解树共 6 类，用 ECharts / D3 重做，视觉接近但不逐像素相同。

## 2. 复刻策略（分三层，避免"什么都做一半"）

### A 层 · 像素级复刻（必做）

- 布局：直接读 `visual.json` 的 `position`，按 1280×720 绝对定位 + 整体 `transform: scale()` 适配窗口（等同 FitToPage）。
- 视觉对象：KPI 卡、treemap、饼图、柱/条、折线+柱组合（帕累托）、散点、面积图、仪表盘、表格/透视表、切片器、文本框、形状、按钮、图片。
- 配色：全部取自 Sime 主题；缺省系列色按 `dataColors` 顺序。
- 字体层级与数字格式：`¥ #,0 M`、`0.0%`、`#,0`、`x.x'h'`。

### B 层 · 等价替代（视觉接近，交互差异需说明）

| PBI 视觉 | 替代方案 | 差异 |
|---|---|---|
| `ChordChart`（供应商 × 类别弦图） | d3-chord 手写 / ECharts graph circular | 弧度与标签排布略不同 |
| `ClusterMap`（类别聚类气泡） | ECharts graph（力导向 + 自定义布局） | 布局算法不同 |
| `geos_bi`（Company 页地图） | ECharts map + effectScatter | 底图更换为合规 geojson |
| `shapeMap`（Geo 页地图） | ECharts map（复用 PBI 的 ShapeMap geojson） | 着色分档一致，缩放行为略不同 |
| `decompositionTreeVisual` | 自研下钻树（点击逐层展开） | 无 AI 拆分建议 |
| `htmlContent`（Card Sales YoY） | 直接渲染同一段 HTML/CSS | 无 |
| `actionButton` + bookmark（Summary/YoY/帕累托/分解树切换） | 纯前端切换（显隐 visual 组） | 无 bookmark 延迟 |

### C 层 · 降级或不做（先明确边界）

- 工具提示页（3 个）：改为 **悬浮卡片**，不单独成页。
- `Card Test` / `Information`：测试与说明页，复刻为「说明」入口。
- PBI 的"钻取筛选其他视觉对象"（cross-filter）：v1 只做**切片器 → 全局筛选**，图表点击联动放到 P2。
- 导出 Excel / 订阅 / 行级权限：不做。

## 3. 数据层方案（**需拍板**）

### 方案 A（推荐）· 与 PBIP 同源

新增导入脚本 `import_dash.py`，把 xlsx 落成两张表：

```sql
CREATE TABLE dash_po (          -- 41,847 行 × 34 列，列名与 PBIP 完全一致
  "No." TEXT PRIMARY KEY, "Date" TEXT, "Company" TEXT, "Company_cn" TEXT, ...
  "Total Price" REAL, "Time Taken" REAL, ...
);
CREATE TABLE dash_calendar (    -- 2023-01-01 ~ 2028-12-31，含自然年 + 财年字段
  "Date" TEXT PRIMARY KEY, "Year" INT, "Month" INT, "年月" TEXT, "年季度" TEXT,
  "FiscalYear" INT, "FiscalYearName" TEXT, "FiscalQuarter" INT, "FiscalMonthNumber" INT,
  "MonthName" TEXT, "MonthNameShort" TEXT, "YearMonthSort" INT, ...
);
CREATE TABLE dash_fa (...)      -- 框架协议 + 前置审批（Contract 页）
CREATE TABLE dash_geo (...)     -- 经纬度
CREATE TABLE dash_logo (...)    -- 品牌 logo svg 映射
```

- 幂等：`DELETE FROM dash_po` 后整表重灌（41k 行约 2~3 秒），或按 `No.` upsert。建议整表重灌 + `VACUUM` 之外不动其它表。
- 金额清洗：xlsx 里 `Total Price` / `Contract Value` 已是数值，直接 `REAL`；若源含文本则复用 `transform.num_expr()` 规则。
- 优点：**所有 PBI 数字可逐一对表**；缺点：依赖 OneDrive 的 xlsx 更新节奏（需要人/脚本定期重导）。

### 方案 B · 从 `procurement.db` 重建

用 `fct_prpo` + `dim_company_map` + `dim_agg_*` 拼出同 34 列。

- 能对上的：`No.`=`表单编号`、`Date`=`提交日期`、`Company`=`公司`、`Category`=`采购类别`、`Sub-Category`=`Table - 采购子类别`、`Total Price`=`含增值税总价`(清洗)。
- **需要逆向**：`Region/City`（`dim_company_map` 有）、`Brand`（有）、`Expense Type`（映射表）、`FY`（按提交日期推）、`Budget Type`（预算字段）、`DT-related`（字段）、`Time Taken`（审批-提交，小数天，口径未知）、`Contract Value`（框架协议表取数，口径未知）、`Supplier_en` / `Category Detail`（供应商表补）。
- 风险：`Time Taken` 与 `Contract Value` 口径不明，重建后**必然对不上 PBI**，会破坏"完全复刻"。
- 成本：约为方案 A 的 2~3 倍，且需要逐列验数。

### 方案 C · 先 A 后 B（推荐落地顺序）

P0 用方案 A 让看板先"数对、视觉对"；上线后再评估是否把 `dash_po` 换成由 `fct_prpo` 生成的视图（`vw_dash_po`），前端零改动。

> 我的建议：**走 A（可平滑切到 C）**。你如果更看重"单一数据源、不再依赖 OneDrive 文件"，那就直接上 B，但要先接受 `Time Taken` / `Contract Value` 两列数字与 PBI 不一致。

## 4. 后端 API（Flask，挂在现有 5000 端口）

新增 `dashboard_api.py`（Blueprint，前缀 `/api/dash`），`app.py` 里 `register_blueprint` + `GET /dash` 返回页面。

| 端点 | 作用 | 参数 |
|---|---|---|
| `GET /api/dash/meta` | 筛选器取值 + 数据范围 + 更新时间 | — |
| `GET /api/dash/kpi` | 单指标（含 PY、YoY、趋势） | `metric`, `fy`, `filters`, `date` |
| `GET /api/dash/kpi-wall` | General 页 30 个 KPI 一次返回（5 指标 × 6 列） | `fy`, `filters` |
| `GET /api/dash/trend` | 月度/季度趋势，可分组堆叠 | `grain`, `group`, `metric`, `filters`, `from`, `to` |
| `GET /api/dash/agg` | 通用分组聚合（treemap/饼/条/散点/透视共用） | `dim`, `metric`, `agg`, `top`, `sort`, `filters` |
| `GET /api/dash/pareto` | 帕累托（金额 + 累计占比 + Top80 标记） | `dim`, `filters` |
| `GET /api/dash/contract` | 框架协议表（含预估金额、使用率） | `filters`, `page` |
| `GET /api/dash/detail` | 明细表 / 下钻（Cumulative、Category Detail） | `rows`, `cols`, `filters` |

约定：

- 筛选条件统一 `filters={"brand":[...],"region":[...],"category":[...],"method":[...],"company":[...],"department":[...],"city":[...],"supplier":[...]}`（JSON 或重复 query），**空数组 = All**。
- 所有金额返回数值（CNY），格式化交给前端（`¥1,476.21M`），汇率切换只改前端乘除 —— 与 PBI 的 `Currency Param` 等价。
- 加一层 `functools.lru_cache`（key=参数 JSON），41k 行聚合实测 < 20ms；meta 缓存 60s。

## 5. DAX → SQL 迁移规则

| DAX 模式 | SQL 实现 |
|---|---|
| `SUM(PO[Total Price])` | `SUM("Total Price")` |
| `CALCULATE(SUM(x), cond)` | `SUM(CASE WHEN cond THEN x END)` |
| `DISTINCTCOUNT(Supplier_cn)` | `COUNT(DISTINCT Supplier_cn)` |
| `COUNT(No.)` | `COUNT("No.")` |
| `MEDIAN(Time Taken)` | SQLite 无 MEDIAN → `ROW_NUMBER()` 取中位（奇偶两行平均）或前端取原始值计算（推荐后者，分组数少） |
| `DIVIDE(a,b)` | `CASE WHEN b=0 OR b IS NULL THEN NULL ELSE a*1.0/b END` |
| `SELECTEDVALUE(Currency[Rate],1)` | 前端传 `rate` 参数，SQL 不参与 |
| `CALCULATE(..., FiscalYear = FY-1)` | 自关联同表按 `FiscalYear = :fy-1` 聚合后 JOIN |
| `REMOVEFILTERS(...)` / `ALL(...)` | 子查询/CTE，不带筛选条件 |
| `DATESINPERIOD` + `AVERAGEX` | 参数化窗口：`BETWEEN date(:d,'-N months') AND :d` 后 AVG |
| 累计占比（`5_Cumulative Amount_by supplier`） | `SUM(s) OVER (ORDER BY s DESC ROWS UNBOUNDED PRECEDING)/SUM(s) OVER ()` |
| `Is Top 80%` | 上式的累计占比 `<= 阈值` 标记 |

三条必须遵守的迁移纪律：

1. **不要用 `fct_prpo` 的 `财政年度`** 去筛期间 —— 该字段在库里不可靠；一律用 `Date` + `dash_calendar`。
2. 金额空串 → `NULL`，不要 `CAST('' AS REAL)`（会得 0）。
3. 时间对比一律走 `dash_calendar` 的 `FiscalYear / FiscalMonthNumber`，与 PBI 的财年定义（4 月起始）保持一致。

## 6. 前端架构

```
dash/
├─ index.html                # 单页，路由用 hash：#/home #/general #/geo ...
├─ css/theme.css             # Sime 令牌 + 组件样式
├─ js/app.js                 # 路由、全局筛选、缩放、页面挂载
├─ js/api.js                 # 请求封装 + 缓存
├─ js/components/            # kpi.js / slicer.js / table.js / pivot.js / tooltip.js
├─ js/charts/                # echarts 配置生成器（bar/line/pie/treemap/scatter/map/gauge）
├─ js/pages/                 # home.js general.js geo.js company.js category.js ...
└─ vendor/                   # echarts.min.js / d3.min.js（本地，内网可用）
```

关键实现点：

1. **画布缩放**：`stage 1280×720` + `scale = min(w/1280, h/720)`，`transform-origin: top left`，外层容器居中。所有 visual 用绝对定位 `left/top/width/height`（直接来自 `position`），这样与 PBI 逐像素对位。
2. **KPI 卡**（30 个）：自研组件 —— 大数字 + PY 目标 + 迷你趋势（SVG sparkline）+ 差值三角（▲绿/▼红，按 PBI 的 good/bad 色）。一次 `/kpi-wall` 拿全，避免 30 次请求。
3. **筛选器**：左侧固定 6 项（Brand / Region / City / Company / Department / 财年），多选 + 搜索 + 全选/清空。PBI 是"改完点按钮才刷"，网页端改为**即时生效**（体验更好），但不做自动轮询。
4. **图表**：ECharts 统一主题（`echarts.registerTheme`），网格线 `#EEF1F6`、轴文字 11px `#6B7280`、无轴线。
5. **表格/透视**：自研轻量表格（排序、分组小计、条件格式条），不用第三方表格库，保证样式可控。
6. **地图**：ECharts `map` + 合规 GeoJSON（阿里 DataV 行政区划），省会/城市名与 `City_en` 对齐；**不使用境外底图服务**，页脚保留数据来源与审图号说明。

1. **PBIP 里的 `preserveAspectRatio='meet'` 浏览器不认**，只认 `'xMidYMid meet'`，直接注入会刷 `console error`（回归测试会红）。注入前正则改成合法值。

## G.7 两个实测踩坑（已修）
1. **`export.csv` 的 SQLite 连接被提前关闭**：视图里 `try/finally: c.close()` 在 `return Response(gen())` 时立即执行，而生成器要等 Flask 消费时才跑，于是 `c.execute()` 报 closed、下载断在表头后（curl exit 18、只收到 142 字节）。修法：把 `c.close()` 移进生成器的 `finally`，视图只留异常路径关闭。现在 1.19 MB / 4,869 行完整下载。

## G.9 执行率口径：PA 只算「通过框架协议方式申请」的采购单（用户 11-19 要求）

用户要求「执行率一定要采购方法是通过框架协议方式申请的才计入」。查 PBI 原始度量值确认口径：

```dax
1_Frame Contract = CALCULATE(SUM(PO[Total Price]), PO[Exception Reason]="Framework Contract")
```

- `PO[Exception Reason]` 在 `dash_po` 里就是 `Exception Reason` 列，源头 `fct_prpo."豁免单一来源的理由"`。
- **CSV 源里实际值是 `Ongoing Frame Contract`，不是 PBI 度量值写的 `Framework Contract`**（同一语义的不同措辞）；视图里必须用 `Ongoing Frame Contract` 才能命中。
- 判定：`fct_prpo` 中 `TRIM(COALESCE("框架合同编号",''))<>''` **且** `TRIM(COALESCE("豁免单一来源的理由",''))='Ongoing Frame Contract'` 的行才计入 agg 的 `实际采购额` / 单据数 / 门店数 / 供应商数 / 首末采购日期，进而影响 `执行率 = 实际采购额 / 预估金额`。

**实现**：改 `vw_fa_analysis` 视图的 `agg` CTE，在 `WHERE 框架合同编号<>''` 后加上面第二个条件。旧视图 SQL 备份在 `.shot/vw_fa_analysis_<时间戳>.sql.bak`。

**为何数字没变**：当前库里 13,764 行有框架合同编号的单，豁免理由 **100% 都是 `Ongoing Frame Contract`**（另 4 行是 Ongoing Frame Contract 但无合同编号，不计入）。所以改前后逐协议差异 = 0，总额仍 406.81M、看板整体执行率仍 38.62%。**口径固化的价值在于防止将来混入非框架协议方式的单**（如 Contract Modification、Principal Purchases 等理由的行若填了合同编号，旧口径会误算）。

**可见性**：卡片标题加 `PA 仅统计框架协议方式采购单`，Usage 列头 `title` 提示同文案；测试加 3 条断言（视图 SQL 含条件、卡片标注、列头提示），共 **73/73 全绿**。

## G.17 供应商英文名缺空格怎么修（11-20）

**现象**：源系统里同一个人/公司常被录成两种写法 —— 有空格的和没空格的：

```
AfloweraOu(Guangzhou)e-commercestudio      ← 吞了空格
A flower a Ou (Guangzhou) e-commerce studio ← 正常
DongguanZhongfanautosuppliesCo.,LTD
```

`fct_supplier.Vendor Name` / `dash_po.Supplier_cn` 里 8,201 个英文名，**1,827 个完全无空格（22.3%）**。

**修复思路：不用人工改，用「同一个名字的另一份写法」当字典。**

1. 把英文名归一成指纹：`lower()` 后去掉所有非字母数字（空格、标点、括号全去掉）。
2. 扫全库的供应商名，凡是有空格的写法就按指纹登记，**同一指纹取空格最多的那份当标准写法**。
3. 遇到无空格的名字，查指纹 → 命中就用标准写法，未命中原样返回。

实测命中率：`dash_po + fct_supplier` 口径 **1,690 / 1,827 = 92.5%**；只看 `dash_po` 是 67%。
落地后 `dash_po` 里 1,876 个无空格名字修好 **1,766 个（94.1%）**，框架协议 124 家供应商**全部**不再连写。

**实现**
| 文件 | 作用 |
|---|---|
| `supplier_name.py`（新） | `compact()` 指纹、`split_en()` 取英文段、`english_variants()` 建字典（按库文件 mtime 缓存）、`clean_en()` / `en_of()` 补空格、`overrides()` 读手工兜底 |
| `supplier_en_overrides.json`（新） | 手工兜底：`{"原写法": "标准写法"}`，改完刷新即生效（按 mtime 缓存），不用重启 |
| `board_api.py` | Top10 / 热力图每行多回 `en`；协议表 `supplier_en` 走 `clean_en`；`_with_en()` 统一处理 |
| `board.js` | 图内标签用 `r.en || supEn(r.k)`；`supEn()` 在离线快照里用内嵌 `enFix` 补空格（保证在线/离线一致） |
| `board_export.py` | 生成 `enFix`（英文原名 → 补好空格的名字，1,766 条，约 160KB）塞进快照 |

**没解决的 6%**：纯拼音（`shenzhennanyouwaifurenliziyuanyouxiangongsi`）和缩写（`HZSXHLR`），没有对照写法也无从推断，落进 `supplier_en_overrides.json` 手写即可（目前填了 3 条协议供应商）。

**原则**：只改显示。`dash_po.Supplier_cn`、`fct_supplier.Vendor Name` 原文一格不动，清洗结果只出现在接口的 `en` / `supplier_en` 与快照的 `enFix` 里 —— 与「双轨数字化」约定一致（事实表留原文）。

| Profit | 金额 | `SUM("含增值税总价")` → `pareto.rows[].v` |

- 新卡片 `#catCard`，**g5**（左），热力图 `Top 10 Suppliers × Category` 由 **g12 改 g7**（右），两卡同一行。

## G.22 月度图补第二种图示：Total vs Framework Contract（11-20）

用户给了参考图（每月两根柱 + 柱顶金额胶囊 + 圆点图例），要求「补充图示样式，契合主题，**原来的也保留，可点击切换**」。

### 两种图示

| 模式 | 标题 | 内容 | 交互 |
|---|---|---|---|
| `region`（默认） | Monthly Spend by Region | 按财月堆叠、颜色=区域；虚线=上期同月总额；画满 12 个月体现实进度 | 点柱 → 按区域交叉筛选 |
| `pair` | Total vs Framework Contract | 每月两根柱：Total（`#1E2F4B`）/ Framework Contract（`#E66C37`）；柱顶深藏青胶囊标金额；月份用全称 | 点柱 → 抽屉下钻该月（`{fm: n}`） |

切换控件 `.seg-sw`（两段式，选中态 `--navy` 底白字）放在卡片标题栏 `.card-tools` 最左，`S.mMode` 记状态，`renderMonthly()` 分发到 `renderMonthlyRegion()` / `renderMonthlyPair()`。

### 数据（一条 SQL 出两个口径）

`/api/board/data` 的 `monthly` 现在同时带两套：

```sql
SELECT c."FiscalMonthNumber" fm,
       COALESCE(NULLIF(TRIM(p."Region_cn"),''),'Unassigned') r,
       SUM(p."Total Price") v,
       SUM(CASE WHEN p."Exception Reason" = 'Ongoing Frame Contract'
                THEN p."Total Price" ELSE 0 END) frm
FROM dash_po p JOIN dash_calendar c ON p."Date"=c."Date" WHERE …
GROUP BY 1,2
```

返回 `{labels, labelsLong, series, total, frame, cur, prev}`。`cur` 是旧字段（tooltip 用过），保留等于 `total`。

**框架协议判据与执行率同源**：`"Exception Reason"='Ongoing Frame Contract'` 原始值，**不做映射**。

### 版式细节

- 只画到「最后一个有数的月份」（`n = lastIndex + 1`），财年进行中时右侧不留大片空白；**region 视图仍画满 12 个月**，两种视图各自成立。
- 柱宽 `min(30, (slot*0.52-gap)/2)`；4 个月时 slot≈250、柱宽 30。
- **不凑整刻度**：`ymax = peak * 1.22`（这张图没有 y 轴数字，`niceMax()` 会把 72 抬到 100，柱高只剩 60%）。
- 柱顶胶囊：`mCap()` 生成 `<rect rx=7.5>` + 白字，宽按字数估（`len*5+11`）。
- **胶囊防重叠**：按月先 Total 后 Frame，用矩形相交检查，撞上就跳过该胶囊（参考图靠柱高差错开，我们再加一道兜底）。
- 网格线 `#F0F0F0`、底轴 `#D9D9D9`、无 y 轴刻度（对齐参考图）。
- 图例改圆点：`Total Amount` / `Framework Contract`。

### 坑

1. **`monthly` 结构不能只改不兼容**：旧 tooltip 读 `monthly.cur`，旧图读 `monthly.series`。这次后端一次返回两套 + `cur`，避免前端崩（此前 `board_api` 已改成只有 `total/frame`，但服务没重启，重启即白屏）。
2. 一张卡片标题栏同时放「切换 + `?` + 图例」在 g8 宽度下刚好一行，窄屏（<1280）会换行，属预期。
3. 离线快照要同步：`board_export.py` 的 `ROW_SQL` 增列 `Exception Reason`（`ROW_COLS` 加 `"exc"`），`snapshot.js monthlyOf()` 用 `r.exc === 'Ongoing Frame Contract'` 算 `frame`，并返回 `labelsLong/total/frame`。快照体积 4.28 → **4.40 MB**。
4. 检验不能只看 DOM：`page.evaluate` 里返回 DOM 元素数组会被序列化成 `{}`，断言 `caps[0].textContent` 会 undefined —— 先 `.map(t => t.textContent)`。

**测试**：在线 `board_check.js` **265 条**（新增 8.7 节 14 条：切换控件 / 默认视图 / 柱数 = 有效月×2 / 每柱一胶囊 / 胶囊金额与接口一致 / 图例切换 / 月份全称 / 点柱下钻 / 切回后数量与图例复原）；离线 `snapshot_check.js` **60 条**全绿。
